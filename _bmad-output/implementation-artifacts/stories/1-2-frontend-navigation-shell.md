# Story 1.2: Frontend Navigation Shell

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a user,
I want a persistent navigation structure to access the Clientes and Contactos sections of the application,
so that I can move between sections without full page reloads from any device.

## Acceptance Criteria

1. **Given** the application is loaded on a desktop browser (≥1024px), **when** the user views the app, **then** a `NavigationRail` (siesa-ui-kit) is visible on the left side (72px collapsed, icon-only) with "Clientes" and "Contactos" entries, and a `Navbar` (siesa-ui-kit) is visible at the top with `productName="Siesa Agents"`.

2. **Given** the desktop navigation shell is rendered, **when** the user clicks the "Clientes" item in the NavigationRail, **then** the router navigates to `/clientes` without a full page reload (FR28), and the Clientes item shows the active state (`primary-600` left border, `primary-50` background).

3. **Given** the desktop navigation shell is rendered, **when** the user clicks the "Contactos" item in the NavigationRail, **then** the router navigates to `/contactos` without a full page reload (FR28), and the Contactos item shows the active state.

4. **Given** the application is loaded on a mobile browser viewport (<1024px), **when** the user views the app, **then** the `NavigationRail` is hidden and a `NavigationBar` (siesa-ui-kit) is displayed at the bottom with "Clientes" and "Contactos" entries, all tappable with minimum 44×44px touch targets (FR29).

5. **Given** the user types `/clientes` directly in the browser URL bar, **when** the page loads, **then** the Clientes view is rendered and the Clientes nav item is shown as active — no redirection to a home screen occurs (FR30).

6. **Given** the user types `/contactos` directly in the browser URL bar, **when** the page loads, **then** the Contactos view is rendered and the Contactos nav item is shown as active — no redirection to a home screen occurs (FR30).

7. **Given** the user navigates to an unknown route (e.g., `/foo`), **when** the page loads, **then** a 404 / not-found view is displayed gracefully with a message in Spanish and a link back to `/clientes`.

8. **Given** the root path `/` is accessed, **when** the page loads, **then** the router redirects to `/clientes` without showing a blank page.

9. **Given** the application shell is rendered on any viewport, **when** the page is inspected with an accessibility tool, **then** all icon-only navigation buttons have `aria-label` in Spanish ("Ir a Clientes", "Ir a Contactos"), the `NavigationRail` has `role="navigation"` and `aria-label="Navegación principal"`, and there are no axe `critical` or `serious` violations (WCAG 2.1 AA).

## Dev Notes

### Architecture Context

This story builds the navigation shell on top of the project scaffold from Story 1.1. No business logic, no domain entities, and no API calls are introduced here. The views for `/clientes` and `/contactos` are placeholder stubs — they will be fully implemented in Epics 2 and 3.

- **Routing:** TanStack Router file-based (`@tanstack/router-plugin`). Route files live under `src/routes/`. The `routeTree.gen.ts` is auto-generated — never edit it manually.
- **Navigation shell:** siesa-ui-kit `LayoutBase` is the mandatory shell. `NavigationRail` for desktop, `NavigationBar` for mobile. No custom navigation component — use siesa-ui-kit AS-IS.
- **No microfrontend:** This is a standalone SPA. Single-SPA rules do not apply.

### TanStack Router File-Based Route Conventions

```
src/routes/
  __root.tsx              # Root layout — wraps all routes, contains LayoutBase + nav
  index.tsx               # / → redirect to /clientes
  clientes.tsx            # /clientes — placeholder (Epic 2 will replace)
  contactos.tsx           # /contactos — placeholder (Epic 3 will replace)
  not-found.tsx           # $catch-all → 404 view
```

**TanStack Router redirect from index:**
```typescript
// src/routes/index.tsx
import { createFileRoute, redirect } from '@tanstack/react-router'

export const Route = createFileRoute('/')({
  beforeLoad: () => {
    throw redirect({ to: '/clientes' })
  },
})
```

**TanStack Router `__root.tsx` pattern:**
```typescript
import { createRootRoute, Outlet } from '@tanstack/react-router'
import { LayoutBase, Navbar, NavigationRail, NavigationBar } from 'siesa-ui-kit'

export const Route = createRootRoute({
  component: AppShell,
})

function AppShell() {
  // configure navigationItems, wrap with LayoutBase
  return (
    <LayoutBase
      navbar={<Navbar productName="Siesa Agents" />}
      navigationRail={<NavigationRail items={navigationItems} />}
      navigationBar={<NavigationBar items={navigationItems} />}
    >
      <Outlet />
    </LayoutBase>
  )
}
```

### siesa-ui-kit Components Required

| Component | Usage |
|-----------|-------|
| `LayoutBase` | Shell container — Navbar 64px + NavigationRail 72px + content area |
| `Navbar` | Top bar with `productName="Siesa Agents"` |
| `NavigationRail` | Left nav, collapsed 72px icon-only, desktop (≥1024px) |
| `NavigationBar` | Bottom nav, mobile (<1024px) |

**Check siesa-ui-kit catalog before creating any custom navigation component. Do NOT build a custom nav if these components exist.**

### Design Spec (from UX Design Specification)

**Desktop layout (≥1024px):**
```
┌─ Navbar (64px) ──────────────────────────────────┐
│  Siesa Agents                                     │
└───────────────────────────────────────────────────┘
┌─ NavigationRail (72px) ─┬─ Content Area ──────────┐
│  👥 Clientes (active)   │  <Outlet />             │
│  🙋 Contactos           │                         │
└─────────────────────────┴─────────────────────────┘
```

**Mobile layout (<1024px):**
```
┌─ Navbar (64px) ─────────────────────────────────┐
│  Siesa Agents                                    │
├──────────────────────────────────────────────────┤
│  <Outlet /> — single column content              │
├──────────────────────────────────────────────────┤
│  NavigationBar (56px) — Clientes | Contactos     │
└──────────────────────────────────────────────────┘
```

**Active nav item style:** `primary-600` left border (3px), `primary-50` background, `primary-700` icon color.

### Navigation Item Configuration

```typescript
import { UsersIcon, UserIcon } from '@heroicons/react/24/outline'

const navigationItems = [
  {
    label: 'Clientes',
    href: '/clientes',
    icon: UsersIcon,
    ariaLabel: 'Ir a Clientes',
  },
  {
    label: 'Contactos',
    href: '/contactos',
    icon: UserIcon,
    ariaLabel: 'Ir a Contactos',
  },
]
```

**Icons:** Heroicons 24px outline (`@heroicons/react/24/outline`). Heroicons is the primary icon library per company standards.

### Not-Found (404) View

```typescript
// src/routes/not-found.tsx (or as notFoundComponent in __root.tsx)
export function NotFoundView() {
  return (
    <div role="main" aria-label="Página no encontrada">
      <h1>Página no encontrada</h1>
      <p>La página que buscas no existe.</p>
      <a href="/clientes">Ir a Clientes</a>
    </div>
  )
}
```

All text MUST be in Spanish. No English user-facing text anywhere.

### Frontend Key Rules (Reminders)

- Package manager: **pnpm** only
- TypeScript strict mode: NO `any` type
- All user-facing text in **Spanish** — labels, ARIA labels, error messages, placeholder text
- Code identifiers (variables, functions, types) in **English**
- Heroicons for icons (primary library per company standards)
- siesa-ui-kit → shadcn → custom (priority order — check siesa-ui-kit FIRST)
- WCAG 2.1 AA: all interactive elements ≥44×44px touch targets, all text meets 4.5:1 contrast ratio

### Detected Conflicts / Variances

- Architecture.md shows `_app.tsx` as a pathless layout route and `_app/clientes.tsx` as a nested route. For Story 1.2 (shell only), a simpler top-level route structure (`clientes.tsx`, `contactos.tsx`) is sufficient as placeholders. Epic 2/3 will introduce the nested `_app/` structure when the full split-panel layout is needed.
- Architecture.md mentions a `LayoutBase` from siesa-ui-kit as the shell. The exact API (prop names) should be verified against the siesa-ui-kit catalog at implementation time — use AS-IS without style overrides.
