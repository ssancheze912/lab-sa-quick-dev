# Story 1.2: Frontend Navigation Shell

Status: ready

## Story

As a user,
I want a persistent navigation structure to access the Clientes and Contactos sections of the application,
so that I can move between sections without full page reloads from any device.

## Acceptance Criteria

1. **Given** the application is loaded on a desktop browser (viewport >= 1024px), **When** the user views the app, **Then** a NavigationRail (siesa-ui-kit `NavigationRail`) is visible on the left side (72px icon-only collapsed) with "Clientes" and "Contactos" entries rendered using Heroicons.

2. **Given** the application is loaded on a desktop browser, **When** the user clicks "Clientes" in the NavigationRail, **Then** the browser navigates to `/clientes` without a full page reload and the "Clientes" item renders in its active state.

3. **Given** the application is loaded on a desktop browser, **When** the user clicks "Contactos" in the NavigationRail, **Then** the browser navigates to `/contactos` without a full page reload and the "Contactos" item renders in its active state.

4. **Given** the application is loaded on a mobile browser (viewport < 1024px), **When** the user views the app, **Then** a NavigationBar (siesa-ui-kit `NavigationBar`) is displayed at the bottom instead of the NavigationRail, and all navigation items ("Clientes", "Contactos") are visible and tappable with adequate touch targets (>= 44px).

5. **Given** the user types `/clientes` directly in the browser URL bar and presses Enter, **When** the page loads, **Then** the Clientes view is rendered and the NavigationRail/NavigationBar marks "Clientes" as active — no redirect to a different route occurs.

6. **Given** the user types `/contactos` directly in the browser URL bar and presses Enter, **When** the page loads, **Then** the Contactos view is rendered and the NavigationRail/NavigationBar marks "Contactos" as active — no redirect to a different route occurs.

7. **Given** the user navigates to any unknown route (e.g., `/ruta-inexistente`), **When** the page loads, **Then** a 404/not-found view is displayed in Spanish with a link that returns to `/clientes`, and no blank screen or unhandled error is shown.

8. **Given** the application root `/` is accessed, **When** the page loads, **Then** the user is redirected to `/clientes` automatically.

## Dev Notes

### Frontend Architecture Context

This story builds on the shell skeleton created in Story 1.1. The `__root.tsx` root route already exists as a placeholder — it must be replaced with the full LayoutBase shell.

**Routing structure (TanStack Router file-based):**
```
src/routes/
  __root.tsx              ← Root layout: LayoutBase + NavigationRail/NavigationBar
  index.tsx               ← Redirect → /clientes
  _app.tsx                ← Pathless layout route (no URL segment)
  _app/
    clientes.tsx           ← /clientes
    contactos.tsx          ← /contactos
  not-found.tsx (or notFoundComponent in __root.tsx)
```

The `_` prefix on `_app.tsx` makes it a pathless layout (TanStack Router convention) — it wraps child routes without adding a URL segment. This means `/clientes` renders inside `_app.tsx`'s `<Outlet />` inside `__root.tsx`'s `<Outlet />`.

**TanStack Router redirect from index:**
```typescript
// src/routes/index.tsx
import { createFileRoute, redirect } from '@tanstack/react-router'

export const Route = createFileRoute('/')({
  beforeLoad: () => {
    throw redirect({ to: '/clientes' })
  },
})
```

**Active link detection with TanStack Router Link:**
```typescript
// Use activeProps in Link to apply active styling
<Link
  to="/clientes"
  activeProps={{ className: 'text-primary-600 bg-primary-50' }}
  inactiveProps={{ className: 'text-slate-600' }}
>
  Clientes
</Link>
```

### siesa-ui-kit Component Lookup

Per company standards, siesa-ui-kit must be checked first before any custom component. The UX Design Specification (Direction F) explicitly specifies:

- `LayoutBase` — main app shell with Navbar + NavigationRail + content area
- `NavigationRail` — collapsed 72px icon-only rail for desktop
- `NavigationBar` — bottom navigation bar for mobile
- `Navbar` — top bar with `productName="Siesa Agents"`

If any of these components are not available in siesa-ui-kit, fall back to shadcn/ui primitives. If shadcn is also unavailable, build a minimal custom version that matches the UX spec layout:

```
Desktop layout:
┌─ Navbar (64px) ─────────────────────────────────────┐
│  Siesa Agents                                        │
└──────────────────────────────────────────────────────┘
┌─ NavigationRail (72px) ─┬─ Content Area ─────────────┐
│  👥 Clientes (active)   │  <Outlet />                 │
│  🙋 Contactos           │                             │
└─────────────────────────┴────────────────────────────┘

Mobile layout (< 1024px):
┌─ Content Area ────────────────────────────────────┐
│  <Outlet />                                        │
└────────────────────────────────────────────────────┘
┌─ NavigationBar ────────────────────────────────────┐
│  👥 Clientes    🙋 Contactos                       │
└────────────────────────────────────────────────────┘
```

### Icons

Per company standards, Heroicons is the primary icon library. Use:
- `UsersIcon` (Heroicons) for Clientes
- `UserIcon` (Heroicons) for Contactos

Install if not already present: `pnpm add @heroicons/react`

### Brand Colors (applied via Tailwind)

- Active nav item: `text-[#0e79fd]` (primary brand blue) or `text-primary-600` if token configured
- Inactive nav item: `text-slate-600`
- Navbar background: `bg-white border-b border-slate-200`
- NavigationRail background: `bg-white border-r border-slate-200`

### All User-Facing Text in Spanish (mandatory)

| English | Spanish (use this) |
|---------|-------------------|
| Clients | Clientes |
| Contacts | Contactos |
| Page not found | Página no encontrada |
| Go back to home | Volver al inicio |
| Main navigation | Navegación principal |

### Scope Boundaries

This story creates the **navigation shell only**. The following are explicitly OUT OF SCOPE:

- Any data fetching from the backend API
- Full ClienteListView implementation (Epic 2, Story 2.1)
- Full ContactoListView implementation (Epic 3, Story 3.1)
- Authentication or session handling

The `/clientes` and `/contactos` routes render stub placeholder components — heading text only. The navigation must work and deep linking must work. No data is loaded.

### Test Setup Note

Tests use Vitest + React Testing Library + MSW (configured in Story 1.1). Router tests should wrap components with TanStack Router's `createMemoryHistory` + `RouterProvider` for a test router context:

```typescript
import { createRouter, createMemoryHistory } from '@tanstack/react-router'
import { routeTree } from '../../routeTree.gen'

function createTestRouter(initialPath: string) {
  return createRouter({
    routeTree,
    history: createMemoryHistory({ initialEntries: [initialPath] }),
  })
}
```
