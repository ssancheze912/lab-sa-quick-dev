# Story 1.2: Frontend Navigation Shell

Status: in-progress

## Story

As a user,
I want a persistent navigation structure to access the Clientes and Contactos sections of the application,
so that I can move between sections without full page reloads from any device.

## Acceptance Criteria

1. **Given** the application is loaded on a desktop browser (viewport ≥ 1024px), **When** the user views the app, **Then** the `LayoutBase` shell from siesa-ui-kit is rendered with a `NavigationRail` (72px collapsed, icon-only) on the left side containing "Clientes" and "Contactos" entries, and a `Navbar` at the top with `productName="Siesa Agents"`. (AC-E1.1, FR28)

2. **Given** the application is loaded on a desktop browser, **When** the user clicks the "Clientes" entry in the NavigationRail, **Then** the router navigates to `/clientes` without a full page reload (client-side navigation), and the shell layout remains mounted. (FR28)

3. **Given** the application is loaded on a desktop browser, **When** the user clicks the "Contactos" entry in the NavigationRail, **Then** the router navigates to `/contactos` without a full page reload, and the shell layout remains mounted. (FR28)

4. **Given** the application is loaded on a mobile browser viewport (< 1024px), **When** the user views the app, **Then** the `NavigationBar` (bottom nav, 56px) from siesa-ui-kit is displayed instead of the NavigationRail, and all navigation items ("Clientes", "Contactos") are accessible and tappable (WCAG 2.1 AA). (AC-E1.1, FR29)

5. **Given** the user types `/clientes` directly in the browser URL bar, **When** the page loads, **Then** the Clientes view is rendered correctly without redirection to a home screen, and the NavigationRail/NavigationBar indicates "Clientes" as the active item. (AC-E1.3, FR30)

6. **Given** the user types `/contactos` directly in the browser URL bar, **When** the page loads, **Then** the Contactos view is rendered correctly without redirection to a home screen, and the NavigationRail/NavigationBar indicates "Contactos" as the active item. (AC-E1.3, FR30)

7. **Given** the user navigates to the root path `/`, **When** the page loads, **Then** the router redirects to `/clientes` automatically (no blank screen at root).

8. **Given** the user navigates to an unknown route (e.g., `/ruta-inexistente`), **When** the page loads, **Then** a 404 / not-found view is displayed gracefully, and the shell layout (NavigationRail/NavigationBar) remains visible and functional.

## Dev Notes

### Architecture Decisions Applied

- **Routing**: TanStack Router file-based routing (`src/routes/` directory). The `_app` prefix creates a pathless layout route — it wraps child routes without adding a URL segment.
- **Navigation components**: `LayoutBase` + `NavigationRail` + `NavigationBar` from `siesa-ui-kit` (P0 mandatory — check siesa-ui-kit catalog BEFORE any custom implementation).
- **Responsive breakpoint**: `lg: 1024px` (Tailwind v4). Use CSS-only approach (`hidden lg:block` / `block lg:hidden`) — do NOT use JS `matchMedia` or resize listeners.
- **Active route detection**: Use TanStack Router's `useMatch` or `useRouterState` hooks. Do NOT rely on manual URL string comparison.
- **No Zustand store needed**: URL is the single source of truth for navigation state in MVP. No client state store required for this story.

### File Structure

```
frontend/src/
  routes/
    __root.tsx              # Root layout: LayoutBase + NavigationRail + Navbar
    index.tsx               # Redirects → /clientes
    _app.tsx                # Pathless layout route (content area)
    _app/
      clientes.tsx          # /clientes route
      contactos.tsx         # /contactos route
    $404.tsx or notFound.tsx # Not-found route
  modules/
    crm/
      clientes/
        presentation/
          ClientesPlaceholder.tsx
      contactos/
        presentation/
          ContactosPlaceholder.tsx
  shared/
    components/
      NotFound.tsx
```

### siesa-ui-kit Components Required

| Component | Usage | Props |
|-----------|-------|-------|
| `LayoutBase` | Root shell wrapper | `navigationItems`, children |
| `Navbar` | Top header bar | `productName="Siesa Agents"` |
| `NavigationRail` | Desktop left nav (72px collapsed) | `items`, active state |
| `NavigationBar` | Mobile bottom nav (56px) | `items`, active state |

> Before implementing, verify exact prop API in siesa-ui-kit documentation. Use MCP shadcn tool only if a component is NOT available in siesa-ui-kit.

```typescript
// __root.tsx: creates the persistent shell (LayoutBase) with Outlet
// _app.tsx: pathless layout, Outlet renders child route content
```

### Responsive Layout Pattern

```tsx

// NavigationRail: visible on desktop, hidden on mobile
<NavigationRail className="hidden lg:flex" ... />

// NavigationBar: visible on mobile, hidden on desktop
<NavigationBar className="flex lg:hidden" ... />
```
