# Story 1.2: Frontend Navigation Shell

Status: ready-for-dev

## Story

As a user,
I want a persistent navigation structure to access the Clientes and Contactos sections of the application,
so that I can move between sections without full page reloads from any device.

## Acceptance Criteria

1. **Given** the application is loaded on a desktop browser (viewport >= 1024px), **When** the user views the app, **Then** a `NavigationRail` (siesa-ui-kit) is visible on the left side with "Clientes" and "Contactos" entries, and clicking either entry navigates to `/clientes` or `/contactos` without a full page reload (FR28).

2. **Given** the application is loaded on a mobile browser (viewport < 1024px), **When** the user views the app, **Then** a `NavigationBar` (siesa-ui-kit) is displayed at the bottom instead of the rail, and all navigation items are accessible and tappable (FR29).

3. **Given** the user types `/clientes` or `/contactos` directly in the browser URL bar, **When** the page loads, **Then** the correct view is rendered without redirection to the home screen — deep linking works correctly (FR30).

4. **Given** the user navigates to an unknown route (e.g., `/foo`), **When** the page loads, **Then** a 404 not-found view is displayed gracefully within the layout shell.

5. **Given** the navigation shell is rendered, **When** the user clicks "Clientes" or "Contactos", **Then** the active item is highlighted in the navigation component to reflect the current route.

6. **Given** the application shell is rendered, **When** the user is on any valid route, **Then** the navigation rail/bar renders with WCAG 2.1 AA compliant ARIA labels in Spanish (e.g., `aria-label="Navegación principal"`).

## Dev Notes

### siesa-ui-kit Navigation Components (MANDATORY)

This story is a UI story — **all navigation components MUST come from `siesa-ui-kit`** before considering custom implementations.

- **Install**: `siesa-ui-kit` is already installed from Story 1.1 (`pnpm add siesa-ui-kit`)
- **Desktop navigation**: Use `NavigationRail` from siesa-ui-kit — renders vertically on the left side
- **Mobile navigation**: Use `NavigationBar` from siesa-ui-kit — renders horizontally at the bottom
- **Breakpoint threshold**: `lg` (1024px) per architecture document (Cross-Cutting Concerns table)
- **DO NOT** build custom navigation components if siesa-ui-kit equivalents exist

### TanStack Router File-Based Routing

The architecture defines these routes for Story 1.2:

```
frontend/src/routes/
├── __root.tsx              # Root layout (already exists from Story 1.1) — update Outlet wrapper
├── index.tsx               # / → redirect to /clientes (update existing file)
├── _app.tsx                # Pathless layout — navigation shell (_prefix = no URL segment)
├── _app/
│   ├── clientes.tsx        # /clientes — ClientesPage placeholder
│   └── contactos.tsx       # /contactos — ContactosPage placeholder
```

**Pathless layout rules (TanStack Router):**
- `_app.tsx` uses the `_` prefix — it wraps child routes but adds NO URL segment
- Child files go in `_app/` directory — they inherit the layout without URL nesting
- The `Outlet` in `_app.tsx` renders the matched child route

**Route redirect pattern:**
```typescript
// frontend/src/routes/index.tsx
import { createFileRoute, redirect } from '@tanstack/react-router'

export const Route = createFileRoute('/')({
  beforeLoad: () => {
    throw redirect({ to: '/clientes' })
  },
})
```

**Active route detection:**
```typescript
import { useRouterState } from '@tanstack/react-router'

// Inside _app.tsx component
const router = useRouterState()
const currentPath = router.location.pathname
const isClientesActive = currentPath.startsWith('/clientes')
const isContactosActive = currentPath.startsWith('/contactos')
```

### Responsive Layout Pattern

Per company standards (TailwindCSS v4, critical breakpoint `lg: 1024px`):

```tsx
// _app.tsx layout structure
function AppLayout() {
  return (
    <div className="flex h-screen" aria-label="Navegación principal">
      {/* Desktop: NavigationRail on the left, hidden on mobile */}
      <aside className="hidden lg:flex">
        <NavigationRail items={navItems} activeItem={activeItem} />
      </aside>

      {/* Main content area */}
      <main className="flex-1 overflow-auto">
        <Outlet />
      </main>

      {/* Mobile: NavigationBar at the bottom, hidden on desktop */}
      <nav className="lg:hidden fixed bottom-0 inset-x-0">
        <NavigationBar items={navItems} activeItem={activeItem} />
      </nav>
    </div>
  )
}
```

### Project Structure Notes

- `__root.tsx` already exists from Story 1.1 with `data-testid="app-root"`. **Do NOT remove** this attribute — ATDD tests depend on it.
- `index.tsx` already exists from Story 1.1. Update it to redirect to `/clientes` instead of rendering an `h1`.
- `routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin/vite` — never edit manually. It will be regenerated when new route files are saved and `pnpm run dev` is running.
- All new route files must use `createFileRoute` with the correct path string matching the file location.

### Previous Story Learnings (from Story 1.1)

- Vite 8 + TypeScript 6 scaffolded with a single `tsconfig.json` (no `tsconfig.app.json`) — adapt TS path aliases accordingly
- shadcn registry was not accessible from CI environment; siesa-ui-kit was installed from the npm registry via `pnpm add siesa-ui-kit`
- `routeTree.gen.ts` is generated by the Vite plugin on the first build run — ensure `pnpm run dev` is running when creating new route files to trigger regeneration
- React 19 + Vite 8 are in use (not React 18 + Vite 7 as originally specified) — API surface is compatible but be aware of version differences
- `@vitejs/plugin-react` is installed separately (not bundled by default with Vite 8 vanilla template)
